# Агент радіо для Raspberry Pi (лише читання)

Маленька служба на Pi з `meshtasticd`, яка віддає веб-панелі три значення, що панель у Docker сама побачити не може:

| Поле | Звідки | Що показує панель |
|---|---|---|
| `logged` | рядок `Set radio: … power=N` у журналі `meshtasticd` | «Після ліміту регіону» |
| `final` | рядок `Final Tx power: N` (його пише лише змінена прошивка з піднятою стелею) | «Фактично на виході чипа» |
| `cap` + `radio` | `SX126X_MAX_POWER` / `RF95_MAX_POWER` у `/etc/meshtasticd/config.yaml` чи `config.d/*.yaml` (22, якщо конфіги є, а ключа в них немає) | «Стеля чипа» і підбір таблиці потужності на антені |

**Навіщо.** Панель на сервері в Docker бачить лише те, що віддає вузол по TCP API: заданий `tx_power`. Журнал і конфіги
живуть на Pi, тож без агента блок «Радіо → Потужність» показує «—» там, де потрібна фактична потужність. Коли панель
працює на самій Pi, агент не потрібен.

```
панель (Docker, сервер) ──GET /radio.json + токен──► агент (Pi) ──читає──► journalctl -u meshtasticd
                                                                      └──► /etc/meshtasticd/*.yaml
```

## Що агент робить і чого не робить

- Віддає **лише ці чотири поля** (`logged`, `final`, `cap`, `radio`) і час. Нічого не пише, не керує вузлом, не запускає чужих команд:
  журнал читається однією фіксованою командою, лише рядки про потужність.
- **Токен обов'язковий** (заголовок `Authorization: Bearer …`), порівняння сталого часу. Додатково можна обмежити клієнтів за IP.
- Працює від окремого користувача `meshagent` без оболонки й без прав на запис, з жорсткими обмеженнями systemd
  (`ProtectSystem=strict`, `NoNewPrivileges`, без capabilities, 48 МБ пам'яті, лише TCP-сокети).
- `GET /ping` повертає «ok» без жодних даних (перевірка, що служба жива).
- Журнал кешується на 10 с: `journalctl` на Pi важкий, навіть коли панель питає щохвилини.

## Встановлення

З цієї папки на вашому комп'ютері:

```bash
scp mesh-radio-agent.py install.sh chechen@<адреса-Pi>:~/
ssh -t chechen@<адреса-Pi> 'sudo bash ~/install.sh'
```

Інсталятор запитає порт (типово `8097`) і **IP сервера панелі**, якому дозволено питати (Enter: будь-який, але лише з токеном).
Він створить користувача `meshagent`, поставить агента в `/usr/local/lib/mesh-radio-agent/`, згенерує **випадковий токен**
у `/etc/mesh-radio-agent/env` (права 600, читає лише root), створить і запустить службу `mesh-radio-agent`, зробить
перевірку й надрукує адресу та токен для панелі. Токен показується лише в цьому терміналі: перепишіть його одразу.

Якщо на Pi ввімкнено брандмауер: `sudo ufw allow from <IP-сервера-панелі> to any port 8097`.

## Налаштування в панелі

**Система → «Вузли панелі» → ✎ біля вашого вузла:**

- **Агент на Pi:** `http://<адреса-Pi>:8097`
- **Токен агента:** токен з інсталятора

Збережіть. Через кілька секунд у «Радіо → Потужність» з'являться значення. Токен лежить у `data/nodes.json` панелі (права 600, входить
у нічну копію) і **ніколи не віддається браузеру**. Порожня адреса вимикає агента й стирає токен. Для першого вузла можна задати
`MESHPI_AGENT_URL` і `MESHPI_AGENT_TOKEN` у `.env` (діє, поки немає `nodes.json`).

Якщо щось не так, панель пише причину під блоком: «токен не підходить», «IP сервера панелі не дозволено на агенті», «немає зв'язку з агентом».

## Перевірка вручну

```bash
curl -s http://127.0.0.1:8097/ping                                    # на Pi: ok
curl -s -H "Authorization: Bearer <токен>" http://<адреса-Pi>:8097/radio.json
# {"logged": 10, "final": null, "cap": 22, "radio": null, "t": 1792737736}
systemctl status mesh-radio-agent
sudo journalctl -u mesh-radio-agent -n 20
```

`final` = `null` це нормально: рядок «Final Tx power» з'являється лише в зміненій прошивці (збирання з піднятою стелею). Тоді панель
показує «Фактично на виході» як менше з `logged` і `cap`.

## Налаштування агента

У `/etc/mesh-radio-agent/env` (після змін: `sudo systemctl restart mesh-radio-agent`):

| Змінна | Типово | Значення |
|---|---|---|
| `AGENT_TOKEN` | згенеровано | обов'язковий, від 16 символів |
| `AGENT_PORT` | `8097` | порт |
| `AGENT_BIND` | `0.0.0.0` | на якій адресі слухати (можна задати лише адресу Pi у LAN) |
| `AGENT_ALLOW` | порожньо | IP клієнтів через кому; порожньо: будь-який із токеном |
| `AGENT_UNIT` | `meshtasticd` | служба, чий журнал читати |
| `AGENT_CFG_GLOB` | `config.yaml` і `config.d/*.yaml` | де шукати стелю чипа (шляхи через `:`) |

## Видалення

```bash
sudo systemctl disable --now mesh-radio-agent
sudo rm -rf /etc/systemd/system/mesh-radio-agent.service /usr/local/lib/mesh-radio-agent /etc/mesh-radio-agent
sudo userdel meshagent
sudo systemctl daemon-reload
```

## Безпека

HTTP без шифрування: токен іде відкрито в локальній мережі, тож тримайте агента лише в LAN (не відкривайте порт в інтернет) і
обмежте клієнтів через `AGENT_ALLOW` та брандмауер. Дані (потужність передавача й назва модуля) не секретні, але токен не
передавайте нікому. За потреби токен змінюється заміною `AGENT_TOKEN` у файлі, перезапуском служби та новим значенням у панелі.
