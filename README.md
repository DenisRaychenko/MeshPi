# meshpi-docker: веб-панель Meshtastic у Docker

Веб-панель для вузла Meshtastic (чат, вузли, карта, графіки, довкілля, налаштування радіо). Основа: проєкт
**meshpi** (JunioR, ліцензія MIT, див. `LICENSE`). Тут лише веб-частина, змінена під вкладки й сторінку входу
(див. `CHANGES.md`), запакована в Docker. `meshtasticd`, радіо й SPI лишаються на Pi.

```
браузер ──HTTP 8090──► контейнер meshpi ──TCP 4403──► mesh-proxy (Pi) ──► meshtasticd ──► радіо
```

Панель підключається до **mesh-proxy** на Pi (`scripts/mesh-proxy.py`), тому не заважає телефону, екрану й
Telegram-мосту: проксі роздає потік вузла кільком клієнтам одразу.

## Можливості

Огляд зі станом і довкіллям, чат (канали й приватні розмови), вузли з запитами «Маршрут/Сигнал/Показники»,
**карта мережі з маршрутами**, налаштування радіо, пароль і резервні копії. Докладно, з картинками:
**[docs/WEB-PANEL.md](docs/WEB-PANEL.md)**.

Також:

- **Події й сповіщення**: нові вузли, обрані, що пропали, низький заряд, перевантажений ефір, перезапуск і втрата зв'язку; звук і
  вікно браузера, а ще Telegram, ntfy чи вебхук, коли вкладка закрита.
- **Діагностика ефіру**: здоров'я мережі за лічильниками вузла (LocalStats), вимір дальності (Range Test), перевірка безпеки
  (повтори й слабкі ключі, відомий ключ каналу), журнал пакетів із фільтрами й CSV.
- **Планування**: планувальник лінка (рельєф, зона Френеля, бюджет) і прогноз для сонячного вузла; зовнішні сервіси лише за кнопкою.
- **Живий режим схеми мережі** (прапорець, типово вимкнений): пакети летять від відправника через ретранслятора до вашого вузла, стрічка останнього пакета, шухляда «Трафік» і «Програти» останні хвилини (лише відображення, у ефір нічого не йде).
- **Карта очима іншого вузла** (наприклад, роутера, доступного лише по радіо) вмикається й вимикається перемикачем.
- **Доступ**: роль «лише перегляд» і журнал дій; карти працюють без інтернету (Leaflet локально, власний сервер плиток).
- **Автоматика** (вимкнена за замовчуванням, жорсткі обмеження): відповіді за правилами (слово чи regex, інший текст для далеких, `{last_hop}`, випадкова пауза в каналі, відповідь з HTTP чи скрипта) і заплановані оголошення.
- **Аналітика:** «Проблеми мережі» (хто надто довго передає, ретранслятор як єдина точка відмови), «Покриття» (полярна діаграма за напрямками), «Останні показники» (по рядку на вузол), позначка ✈ для вузлів на великій висоті, **геозони** (вхід і вихід вузла) і пошук у повідомленнях.

## Розгортання

> **Повна покрокова інструкція (Pi, Docker, перший вхід, оновлення, проблеми): [docs/INSTALL.md](docs/INSTALL.md).**
> Нижче лише коротко.

Потрібно: хост із Docker + Compose, SSH по ключу, Pi з працюючим `mesh-proxy` на порту 4403.

```bash
./deploy.sh користувач@хост           # копіює файли, збирає образ, піднімає контейнер
./backup.sh --install-cron            # (на хості) нічна копія о 03:45
```

Адреса вузла й адреса, на якій слухає панель, задаються в `.env` на хості (`MESH_HOST`, `MESH_PORT`, `MESHPI_PUBLISH`), а не в
репозиторії; без `MESHPI_PUBLISH` панель слухає лише сам хост.

### Пароль

Перший запуск створює `.env` на хості з випадковим паролем (користувач `admin`). Прочитати:
`ssh <хост> "grep MESHPI_PASSWORD ~/meshpi/.env"`. Змінити можна у вкладці «Система»; новий пароль зберігається
в `data/password` і діє замість `.env`. **Без пароля панель відкрита для всієї мережі.**

## Що де лежить

| Шлях | Призначення |
|---|---|
| `webui/app.py` | сервер Flask (авторизація сесіями, API, кілька підключень, збір довкілля) |
| `webui/admin.py` | керування вузлами: розділи конфігурації, канали, позиція, дії; свій вузол і віддалені по радіо |
| `webui/extras.py`, `webui/notify.py` | чиста логіка нових можливостей (здоров'я мережі, безпека, дальність, лінк, сонце, автоматика) і сповіщення Telegram/ntfy/вебхук; без Flask, тому тестуються окремо |
| `webui/templates/app.html` | єдина сторінка з вкладками; `login.html`: сторінка входу |
| `webui/static/` | `tabs.js` (вкладки), `env.js` (довкілля), `mesh.js` (карта мережі), `events.js`, `health.js`, `rangetest.js`, `plan.js`, `notify.js`, `security.js`, `access.js`, `auto.js`, `role.js`, `logic.js`, `common.js`, `style.css`; `vendor/leaflet/`: Leaflet 1.9.4 локально |
| `pi-agent/` | Агент для Pi (лише читання): віддає панелі потужність і стелю чипа з журналу й конфігів `meshtasticd` |
| `telegram-bot/` | Telegram-міст для Meshtastic (працює на Pi як служба `mesh-telegram`): код, інсталятор, опис |
| `docs/` | `INSTALL.md`: встановлення; `WEB-PANEL.md`: опис можливостей з картинками (`docs/img/`) |
| `Dockerfile`, `docker-compose.yml` | образ без root, файлова система лише для читання, ліміт 256 МБ |
| `backup.sh` | нічна копія бази й налаштувань (14 діб) |
| `tests/` | перевірки входу, довкілля, MQTT, карти мережі, кількох вузлів, адміністрування й нових функцій |
| `tools/` | скрипти, якими `app.html` зібрано з оригінальних сторінок; `docs_demo.py`: демо-сервер для скриншотів |

Дані (`data/`): `messages.db` (історія, графіки, показники довкілля, події, журнал дій), `password`, `viewerpw`, `secret.key` (підпис сесій),
`location.json`, `notify.json` (токени сповіщень), `auto.json`, `auto_state.json`, `solar.json`. Їх немає в git (`.gitignore`).

## Резервні копії та відновлення

Нічний `cron` пише в `~/backups/meshpi`: `messages-*.db` (узгоджена копія SQLite) і `files-*.tgz`
(`.env`, пароль, ключ сесій). Відновлення: зупинити контейнер, повернути `messages-*.db` у `data/messages.db`,
розпакувати `files-*.tgz`, запустити. Увага: копії лежать на тому ж диску; для захисту від виходу карти з ладу
їх треба додатково копіювати на інший пристрій.

## Тести

Потрібні `flask`, `waitress`, `meshtastic` (див. `webui/requirements.txt`):

```bash
python tests/auth_test.py webui     # вхід, сесії, вихід, захист від open-redirect
python tests/env_test.py  webui     # усереднення довкілля, відсів збоїв, прапорець MQTT
python tests/mqtt_test.py webui     # рядок про MQTT, фільтр «без MQTT»
python tests/mesh_test.py webui     # зв'язки з пакетів, добовий архів, /api/mesh, авто-маршрути
python tests/multi_test.py webui    # кілька вузлів, міграція старої бази, дані окремо для кожного вузла
python tests/admin_test.py webui    # адміністрування свого й віддаленого вузла (підставний вузол)
python tests/features_test.py webui # статус доставки, позиція, готові повідомлення, QR, журнал пакетів
python tests/agent_test.py webui    # агент на Pi (токен, кеш, пошук стелі) і його підключення до панелі
python tests/waypoint_test.py webui # точки на карті (прийом, блокування, надсилання), телеметрія вузлів і /api/telemetry
python tests/events_test.py webui   # журнал подій: нові вузли, обрані, що пропали
python tests/health_test.py webui   # здоров'я мережі (LocalStats), відсутність дубльованих маршрутів
python tests/notify_test.py webui   # сповіщення, пороги тривог, токени лише на сервері
python tests/security_test.py webui # перевірка безпеки: повтори й слабкі ключі, ключі каналів
python tests/packets_test.py webui  # фільтри журналу пакетів і CSV (захист від формул)
python tests/role_test.py webui     # роль «лише перегляд», перелік дозволеного, журнал дій
python tests/offline_test.py webui  # Leaflet локально, власний сервер плиток
python tests/range_test.py webui    # вимір дальності (Range Test)
python tests/auto_test.py webui     # автовідповідач і оголошення, їхні обмеження
python tests/plan_test.py webui     # планувальник лінка й прогноз сонця (зовнішні сервіси підроблено)
python tests/netview_test.py webui  # карта «очима вузла»: центр, напрямки, перемикач
python tests/live_test.py webui     # живий режим схеми: потік пакетів /api/live, ретранслятор, повтор за часом
```

## Обмеження в Docker

Кнопки «Перезапустити/Вимкнути плату», журнал `meshtasticd`, редагування `/etc/meshtasticd` і підняття
потужності (збирання прошивки) працюють лише на самому Pi. Вкладка «Радіо» читає й змінює налаштування вузла
через API, це працює й у Docker. «Пошук мережі за пресетами» тимчасово перемикає радіо вузла: запускати свідомо.
