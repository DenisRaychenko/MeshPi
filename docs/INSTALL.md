# Встановлення Meshpi

Покрокова інструкція: від чистого Raspberry Pi до працюючої веб-панелі. Опис можливостей: [WEB-PANEL.md](WEB-PANEL.md).

```
браузер ──HTTP 8090──► контейнер meshpi (Docker) ──TCP 4403──► meshtasticd на Pi ──► радіомодуль
```

Панель це окремий контейнер. Радіо, SPI і служба `meshtasticd` лишаються на Pi, а контейнер лише підключається до
їхнього TCP API. Тому панель можна поставити на **той самий Pi** або на **будь-який інший комп'ютер у вашій мережі**.

## Вимоги

| Що | Вимога |
|---|---|
| Вузол Meshtastic | Raspberry Pi (або інший Linux) із радіомодулем LoRa на SPI, `meshtasticd` 2.7 або новіший |
| Хост для панелі | Linux із **Docker 24+** і **Docker Compose v2**; ~256 МБ пам'яті, ~100 МБ на диску (+ історія) |
| Мережа | хост панелі бачить Pi по TCP, порт `4403`; браузер бачить хост панелі по порту `8090` |
| Доступ | для віддаленого розгортання: SSH по ключу з вашого комп'ютера на хост панелі |

Образ збирається з `python:3.12-slim` і працює на `amd64` та `arm64`/`armv7` (Raspberry Pi 3/4/5, Zero 2 W).
Для Pi Zero 2 W і слабких карт пам'яті збирання образу триває кілька хвилин; можна зібрати на ПК і перенести.

## Крок 1. meshtasticd на Pi

Якщо `meshtasticd` на Pi уже працює й ви бачите вузол у застосунку Meshtastic, переходьте до [кроку 2](#крок-2-docker).

1. Увімкніть SPI: `sudo raspi-config` → Interface Options → SPI → Yes (для окремих плат ще `dtoverlay=spi0-0cs` у
   `/boot/firmware/config.txt`), перезавантажте Pi.
2. Встановіть `meshtasticd` за офіційною інструкцією для Linux Native на сайті Meshtastic (репозиторій пакетів під вашу
   версію Debian/Raspberry Pi OS). Вибір версії: 2.7 або новіша.
3. Підберіть конфіг вашого модуля: скопіюйте відповідний `lora-*.yaml` з `/etc/meshtasticd/available.d/` у
   `/etc/meshtasticd/config.d/` (піни CS/Reset/Busy/IRQ і тип чипа залежать від плати; для E22 це SX1262/SX1268, для
   E32 і Ra-01/02 це `RF95`).
4. Запустіть службу й перевірте:

```bash
sudo systemctl enable --now meshtasticd
systemctl is-active meshtasticd
ss -ltn | grep 4403
```

Має бути `active` і порт `4403` у стані `LISTEN`. У журналі (`journalctl -u meshtasticd -n 50`) не повинно бути помилок
ініціалізації радіо.

5. Задайте **регіон** вузла (наприклад, у застосунку Meshtastic або `meshtastic --set lora.region <РЕГІОН>`):
   без регіону радіо не передає. Регіон і потужність мають відповідати законодавству вашої країни.

> **Один клієнт на порт.** `meshtasticd` обслуговує одне TCP-з'єднання на порт `4403`. Поки панель підключена напряму,
> застосунок на телефоні через цей же порт підключитися не зможе. Якщо треба працювати одночасно з панеллю, телефоном і
> іншими клієнтами, перед `meshtasticd` ставлять проксі, що роздає один потік кільком клієнтам (так налаштовано
> в автора); тоді панель підключається до порту проксі. Без проксі вказуйте порт `4403`.

> **Безпека.** TCP API `meshtasticd` не має пароля. Не відкривайте порт `4403` в інтернет; тримайте його лише в локальній
> мережі (брандмауер або VLAN).

Перевірка з хоста панелі:

```bash
nc -vz <адреса-Pi> 4403
```

## Крок 2. Docker

Якщо Docker уже встановлено (`docker compose version` показує v2), пропустіть крок.

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # щоб користуватися docker без sudo; вийдіть і зайдіть у систему знову
docker compose version
```

## Крок 3. Код і налаштування

Клонуйте репозиторій на хост панелі (або на свій комп'ютер, якщо розгортатимете віддалено через `deploy.sh`):

```bash
git clone <адреса-вашого-репозиторію>/meshpi.git
cd meshpi
```

Адреси не зберігаються в репозиторії: вони задаються в файлі `.env` поруч із `docker-compose.yml` (створіть його на кроці 4,
він у `.gitignore`). Потрібні три значення:

```bash
MESH_HOST=<адреса Pi з meshtasticd або проксі>
MESH_PORT=4403                       # 4403: напряму до meshtasticd або порт проксі, якщо він є
MESHPI_PUBLISH=<адреса хоста>           # де слухати панель; без цього рядка лише сам хост (127.0.0.1)
```

> Адреса в `MESHPI_PUBLISH` має **існувати на хості**, інакше Docker не запуститься («cannot assign requested address»). Якщо
> сумніваєтесь, поставте `0.0.0.0` (слухати на всіх адресах хоста) і обмежте доступ брандмауером.

## Крок 4. Запуск

### Варіант А. На самому хості

```bash
# 1. пароль адміністратора (випадковий; користувач admin)
printf 'MESHPI_USER=admin\nMESHPI_PASSWORD=%s\n' "$(tr -dc 'A-Za-z0-9' </dev/urandom | head -c 20)" > .env
chmod 600 .env

# 2. каталог даних (контейнер працює від користувача 1000:1000)
mkdir -p data
sudo chown 1000:1000 data

# 3. збирання образу й запуск
docker compose up -d --build

# 4. перевірка
docker ps --filter name=meshpi
docker logs --tail 20 meshpi
```

У журналі має з'явитися рядок «підключено до …:4403». Пароль можна прочитати командою `grep MESHPI_PASSWORD .env`.

### Варіант Б. Віддалено з вашого комп'ютера

Потрібні SSH по ключу на хост панелі та Docker на ньому. З папки репозиторію:

```bash
./deploy.sh user@адреса-хоста
```

Скрипт копіює файли в `~/meshpi` на хості, створює `.env` із випадковим паролем (якщо його ще немає), збирає образ і
запускає контейнер. Пароль: `ssh user@адреса-хоста "grep MESHPI_PASSWORD ~/meshpi/.env"`. Попередня версія лишається в
`~/meshpi/webui.prev` для швидкого відкату.

> `docker-compose.yml` береться з вашої копії репозиторію, тож правки з [кроку 3](#крок-3-код-і-налаштування) зробіть
> **до** запуску `deploy.sh`.

## Крок 5. Перший вхід

1. Відкрийте `http://<адреса-хоста>:8090` у браузері. З'явиться сторінка входу.
2. Увійдіть: користувач `admin`, пароль із `.env`.
3. У шапці має горіти **«онлайн»**. Якщо там «Немає зв'язку», дивіться [проблеми](#проблеми-і-рішення).
4. **Змініть пароль:** вкладка «Система» → «Пароль». Новий пароль зберігається в `data/password` і діє замість `.env`.
5. Задайте **розташування плати**: вкладка «Вузол» → «Розташування». Воно потрібне для колонки «Відстань» і азимутів на
   карті мережі, якщо вузол сам не повідомляє координат.

Дані з'являться не одразу: графіки накопичуються з часом, показники довкілля й зв'язки на карті мережі з'являються по
мірі приймання пакетів, а історія телеметрії окремих вузлів (графіки в панелі вузла) копиться з пакетів, які вони
передають самі (зазвичай раз на ~30 хв).

## Крок 6 (за бажанням). Другий вузол

Панель може працювати з кількома вузлами одночасно (кілька Pi з радіо, чи основний і запасний). Умова та сама, що для
першого: хост панелі бачить `meshtasticd` нового вузла по TCP (порт `4403`).

1. Вкладка **«Система»** → блок **«Вузли панелі»** → у формі внизу вкажіть назву (напр. «Дача»), адресу вузла й порт
   `4403` → **«＋ Додати вузол»**.
2. За кілька секунд у списку з'явиться **«на зв'язку»**, а в шапці **селектор вузла** (● назва). Він перемикає всі
   вкладки на вибраний вузол; історія кожного вузла ведеться окремо.
3. Список зберігається в `data/nodes.json` (до 8 вузлів) і входить у нічну копію. Перший вузол завжди береться з
   `MESH_HOST`/`MESH_PORT` у `.env`, поки ви не змінили його в панелі (✎).

## Крок 7 (за бажанням). Керування віддаленими вузлами по радіо

Вкладка **«Керування»** налаштовує не лише підключений вузол, а й **будь-який вузол мережі** через радіо (як «Remote
Administration» в застосунку). Для цього на віддаленому вузлі треба один раз **дозволити ваш вузол як адміністратора**:

1. У панелі: **Керування** → «Цей вузол» → розділ **«Безпека (лише читання)»** → скопіюйте поле **`public_key`**
   (відкритий ключ вашого вузла в base64; приватного ключа панель не показує).
2. На віддаленому вузлі внесіть цей ключ у **`security.admin_key`**: у застосунку Meshtastic це Settings → Security →
   Admin Key; або командою (потрібне пряме підключення до віддаленого вузла, наприклад по USB чи Wi-Fi):

```bash
meshtastic --host <адреса-віддаленого-вузла> --set security.admin_key "base64:<public_key>"
```

   Команда **додає** ключ у список `admin_key` (не замінює його), тож не запускайте її двічі з одним ключем; поточний
   список видно за `meshtastic --host <адреса> --get security`.

3. Дочекайтеся, поки ваш вузол почує NodeInfo віддаленого (він передає його сам, зазвичай раз на кілька годин), бо
   PKC-шифрування потребує його відкритого ключа.
4. Перевірка: **Керування** → у списку «Вузол» оберіть віддалений («· по радіо») → розділ → **«Прочитати»**.
   Відповідь приходить за кілька-кільканадцять секунд. Якщо ні, панель напише причину (див. [проблеми](#проблеми-і-рішення)).

> **Безпека.** `admin_key` дає повне керування вузлом: зміну каналів, ключів і радіо. Тримайте пароль панелі надійним і не
> відкривайте панель в інтернет без TLS. Панель сама нічого не змінює: усе записується лише за вашою кнопкою.

## Після встановлення

**Резервні копії.** На хості панелі раз і назавжди:

```bash
./backup.sh --install-cron
```

Щоночі о 03:45 у `~/backups/meshpi` пишеться копія бази (історія, графіки, зв'язки, телеметрія, точки на карті, події) і файлів
(`.env`, пароль, ключ сесій, список вузлів `nodes.json`, розташування, `notify.json` з токенами сповіщень, `viewerpw`); зберігається 14 діб. Копії лежать на тому ж диску: для надійності періодично копіюйте їх на інший пристрій і **бережіть їх, як пароль**: у них токени ботів.

**Автозапуск.** Контейнер має `restart: unless-stopped` і підніметься після перезавантаження хоста (за умови, що служба
Docker увімкнена: `sudo systemctl enable docker`).

**Доступ ззовні.** Панель працює по HTTP. Для доступу не з домашньої мережі поставте перед нею зворотний проксі з
TLS (nginx, Caddy, Traefik) і додайте в `.env` рядок `MESHPI_COOKIE_SECURE=1`, щоб cookie сесії ходили лише по HTTPS.
Не відкривайте порт `8090` в інтернет напряму.

**Налаштування середовища** (у `.env` або в `environment` у `docker-compose.yml`):

| Змінна | Типово | Призначення |
|---|---|---|
| `MESHPI_USER`, `MESHPI_PASSWORD` | `admin` / з `.env` | вхід у панель |
| `MESH_HOST`, `MESH_PORT` | `localhost` / `4404` | адреса й порт першого вузла (`meshtasticd` чи проксі); додаткові вузли додаються в панелі: Система → «Вузли панелі» |
| `MESHPI_ENV_HOPS` | `3` | не далі скількох стрибків усереднювати довкілля |
| `MESHPI_TRACE_HOPS` | `5` | не далі скількох стрибків питати авто-маршрути |
| `MESHPI_TRACE_EVERY` | `10800` | період кола авто-маршрутів, с |
| `MESHPI_COOKIE_SECURE` | порожньо | `1`, якщо перед панеллю є HTTPS |
| `MESHPI_VIEWER_USER`, `MESHPI_VIEWER_PASSWORD` | `viewer`, порожньо | вхід «лише перегляд» (пароль зручніше задати в «Система → Доступ і журнал дій») |
| `MESHPI_TILE_URL`, `MESHPI_TILE_ATTR`, `MESHPI_TILE_ZOOM` | OpenStreetMap | власний сервер плиток карти: тоді карта працює без інтернету |
| `MESHPI_FAV_OFFLINE` | `1800` | скільки секунд не чути обраного вузла, щоб вважати його «пропалим» |
| `MESHPI_PKT_LOG` | `1000` | скільки пакетів тримати в журналі пакетів на підключення |
| `MESHPI_NO_EXTERNAL` | порожньо | `1` вимикає запити до open-meteo.com (планувальник лінка) і forecast.solar (сонячний вузол) |

**Сповіщення поза браузером** (Telegram, ntfy, вебхук) і пороги тривог налаштовуються в «Система → Сповіщення поза браузером»; токени лежать лише на сервері в `data/notify.json` (права 600). **Роль «лише перегляд»** вмикається там само: «Доступ і журнал дій». **Автоматика** (відповіді й оголошення) вимкнена, доки ви її не ввімкнете, і передає в ефір без вашої участі: читайте попередження в розділі й дотримуйтесь свого ліміту ефіру.

**Авто-маршрути** (типово ввімкнені) раз на 3 години й для нових вузлів по черзі надсилають їм «Маршрут». Це передачі в
ефір; вимикаються прапорцем «авто-маршрути» на вкладці «Мережа» (деталі в [WEB-PANEL.md](WEB-PANEL.md)).

## Оновлення

```bash
./backup.sh                          # на хості панелі: копія бази перед оновленням (займає секунду)
git pull
./deploy.sh user@адреса-хоста        # віддалено
# або на самому хості:
docker compose up -d --build
```

Дані (`data/`) зберігаються. **Міграція бази:** при першому запуску версії з кількома вузлами база автоматично
отримує колонку власника («main»); це одна транзакція, старі дані лишаються й належать першому вузлу. **Відкат** на код,
що старший за цю версію, після міграції без відновлення бази не працює (старий код не знає нової схеми): тоді поверніть
копію `messages-*.db` у `data/messages.db` з `~/backups/meshpi`. Відкат на новіший код (для `deploy.sh`): на хості
перемістіть `~/meshpi/webui.prev` на місце `~/meshpi/webui`, виконайте `docker compose up -d --build`.

## Проблеми і рішення

| Симптом | Причина й рішення |
|---|---|
| У шапці «Немає зв'язку» | хост не бачить Pi: перевірте `MESH_HOST`/`MESH_PORT`, `nc -vz <Pi> 4403` з хоста панелі, брандмауер; чи працює `meshtasticd` |
| Підключення є, але дані не йдуть, а телефон не підключається | порт `4403` обслуговує одного клієнта: закрийте застосунок, що тримає з'єднання, або використайте проксі |
| `permission denied` на `/data` у журналі контейнера | `sudo chown 1000:1000 data` і `docker compose restart` |
| `cannot assign requested address` під час запуску | у `ports` вказано адресу, якої немає на хості: виправте або використайте `"8090:8080"` |
| `port is already allocated` | порт `8090` зайнятий: змініть лівий порт у `ports` |
| Забули пароль | видаліть `data/password` і перезапустіть: діятиме пароль із `.env` (його видно командою `grep MESHPI_PASSWORD .env`) |
| Порожня карта на вкладці «Вузли» | плитки OpenStreetMap завантажує браузер: потрібен інтернет на вашому комп'ютері, або вкажіть власний сервер плиток у `MESHPI_TILE_URL`. Вузли на карті видно й без плиток |
| «Здоров'я мережі» каже «Збираю дані» | вузол шле лічильники LocalStats раз на ~15 хв, потрібні два заміри; за повідомленнями про прошивку 2.7.15 телеметрію пристрою там вимкнено за замовчуванням: за потреби увімкніть її в «Керуванні» (модуль телеметрії) |
| Сповіщення не приходять у Telegram | у «Система → Сповіщення» натисніть «Надіслати пробне»: воно покаже відповідь Telegram по кожному каналу (неправильний токен, бот не доданий у чат) |
| «Вимір дальності» порожній | на вузлі-відправнику не ввімкнено Range Test або його пакети не доходять; без позиції відправника відстань невідома, але SNR все одно записується |
| «Радіо → Потужність» порожнє (—) | панель не на Pi і не бачить журналу meshtasticd: встановіть [агента](../pi-agent/README.md) і вкажіть його в «Система → Вузли панелі» |
| Порожні графіки | вони наповнюються раз на кілька хвилин: зачекайте; перевірте, що вузол «онлайн» |
| Не збирається образ на Pi Zero | замало пам'яті: зберіть образ на ПК (`docker buildx build --platform linux/arm64 ...`) або додайте swap |
| «Керування»: «ключ цього вузла не внесено в security.admin_key» | додайте `public_key` вашого вузла в `security.admin_key` віддаленого ([крок 7](#крок-7-за-бажанням-керування-віддаленими-вузлами-по-радіо)) |
| «Керування»: «невідомий відкритий ключ вузла» / «ще не відомий із відкритим ключем» | ваш вузол ще не чув NodeInfo віддаленого: зачекайте або натисніть «Дані» в панелі вузла (вкладка «Вузли») |
| «Керування»: «Вузол не відповів за 60 с» | слабкий сигнал (дивіться SNR на карті «Мережа»: нижче −15 дБ зв'язок ненадійний) або вузол вимкнений; повторіть пізніше |
| «Керування»: «вже виконується інша адмін-операція» (409) | на одному підключенні операції йдуть по одній: дочекайтеся завершення попередньої |
| Вузол у «Вузлах панелі» «немає зв'язку» | перевірте адресу й порт (✎), `nc -vz <адреса> 4403` з хоста панелі, що `meshtasticd` на ньому запущено і не зайнятий іншим клієнтом |
| «QR і посилання» дає «Канали ще не завантажені» | вузол щойно підключився: зачекайте хвилину, поки панель отримає його канали |
| Порожній список точок на карті | точки з'являються, коли їх надсилають вузли вашого каналу або ви ставите свої кліком; точки з MQTT-мосту ігноруються |

Журнал контейнера: `docker logs -f meshpi`. Вкладки «Радіо», «Вузол» і «Система» частково працюють лише на самій Pi
(перезапуск служб, журнал `meshtasticd`, збирання прошивки); у Docker на іншому хості ці кнопки недоступні, а читання й
запис налаштувань радіо працюють по API.
